## 1. 目标与范围

V2.3 建立一个完整的、与 Manifold 关联的 Drawing Workspace：**工程模型提供事实，Drawing 文档保存排版与标注，发行修订保存不可变的交付记录。**

目标工作流：

1. 打开 Project，选择已有 Manifold。
2. 选择 Create Drawing。
3. 选择 Customer Drawing 或 Manufacturing Drawing。
4. 自动生成有用的工程图初稿。
5. 视觉调整视图、尺寸、文字、标签、表格及标题栏。
6. 保存到 Project，关闭后能够重新打开并继续编辑。
7. 检测源 Manifold 变化，更新图纸并处理关联冲突。
8. 管理图纸修订、历史和发行，必要时记录工程例外。
9. 导出可打印、可提交客户或用于加工交付的矢量工程 PDF。

整个范围作为一个完整的 V2.3 交付。内部先打通两类图纸共用的可用流程，再逐步增强复杂场景；这不是拆分产品版本，也不能用只有客户图或只有截图导出来替代完整 Drawing Workspace。

核心验收包含两种图纸、实用编辑、Project 保存/重开、可靠关联更新、修订/发行和矢量 PDF。SVG/DXF、通用三方合并、高级绘图工具以及通用项目打包不是核心完成的前置条件。制造图实际需要的内部信息、必要剖面和密集图可读性仍必须解决，可以采用明确的人工整理和分页完成。

V2.3 从 Project 中已经存在的 Manifold 开始，统一支持人工设计、AI 辅助设计及现有导入/转换流程产生的 Manifold。绘图操作不需要调用 AI。

实施约束：

- 不改变已有 provider、Max Tokens、timeout、streaming 或 reasoning 配置。
- 不从图纸样本或型号名称推造孔腔几何、兼容性、螺纹、密封座或加工数据。
- 保留确定性 CAD/液压验证、Library 权威、来源追踪及人工复核边界。
- 不将图纸发行状态等同于制造就绪、工程 PASS 或承压认证。
- 不建立第二套 Knowledge Base、制造数据目录、刀具执行系统或独立工程事实编辑中心。

### 2.2 当前代码基础

| 代码位置 | 可复用能力 |
|---|---|
| `manifold/projects.py` | 命名 Project、独立构建指针、历史和保存冲突 |
| `manifold/store.py` | 不可变构建，包括 STEP、最终 `resolved_design`、验证结果和加工清单 |
| `manifold/schema.py` | 稳定 Feature ID、固定 Library 定义、来源及工程复核信息 |
| `manifold/manufacturing.py` | 实际钻孔、切削步骤及加工检查资料 |
| `manifold/cad.py` | 统一 CAD 导入边界与已验证的 Windows DLL 加载顺序 |
| `web/` | 原生 JavaScript/Vite、Three.js、现有编辑交互和局部 SVG 剖面能力 |

当前加工清单仍属于检查资料，部分堵头入口加工明确处于 unresolved 状态。

主要缺口：

- Drawing 文档、保存与视觉编辑器。
- 精确二维投影与关联标注。
- 源变化检测、重新生成和失效引用处理。
- 图纸模板、实用修订/发行及矢量 PDF 输出。
- 少量绘图必需信息可能缺少公共字段；按具体样本/项目核查，不能把全面制造数据补齐设为绘图前置条件。

现有三维查看器和孔腔剖面控件可以复用局部能力，不能直接承担完整工程图工作流。

## 3. 总体架构与主要组件

### 3.1 数据流

```text
Project 中已保存的 Manifold
        ↓
固定工程快照：设计版本、精确构建、Library、原理图
        ↓
精确投影 + 工程尺寸/表格生成
        ↓
Drawing 文档：图页、视图、关联标注、用户调整
        ↓
视觉编辑 → 保存/重开 → 重新生成/处理失效引用 → 发行修订
        ↓
矢量工程 PDF（必须） / SVG、DXF（按适配成本增加）
```

### 3.2 模块划分

建议新增独立的 `manifold/drawing/` 和 `web/drawing/` 模块。

| 模块 | 职责 |
|---|---|
| Drawing schema/store/API | 文档、图页、版本、保存冲突、Project 归属 |
| Source snapshot | 固定并核验设计、构建、库版本和附件 |
| Projection | 先完成正投影、等轴测、隐藏线与必要剖视，再扩展高级剖视/详图 |
| Annotation | 尺寸、中心线、孔标注、引出线、基准和表格 |
| Layout/template | 模板应用、初始排版、避让及分页 |
| Source update | 比较源版本、重新生成、按稳定键保留调整及处理失效引用；复杂匹配后续增强 |
| Revision/release | Draft、修订/历史、Released，保存检查结果和必要的发行说明 |
| Export | 共用矢量内容优先输出 PDF，SVG/DXF 使用独立适配器 |
| Visual workspace | 选择、编辑、图页导航、撤销重做和状态反馈 |

### 3.3 技术选择

- 沿用 FastAPI、原生 JavaScript 模块与 Vite，不进行整套前端框架迁移。
- 编辑画布采用 SVG。
- Three.js 保留用于源模型辅助检查，不作为尺寸计算来源。
- 精确投影使用现有 OCCT 的 BRep 能力。
- Drawing 与 CAD 引擎分别记录版本，纯排版引擎变化不应无故使 CAD 构建失效。
- 本地完成生成、编辑、保存和导出，不新增 AI 调用依赖。
- 生成几何与用户表现从数据结构上分离；先用简单、可测试的规则更新，不依赖通用合并框架。

## 4. Drawing 数据结构、存储与 API

### 4.1 数据模型

Drawing schema 独立版本化。

| 对象 | 关键内容 |
|---|---|
| `DrawingDocument` | ID、Project ID、类型、图号、标题、Draft/Released、独立保存版本 |
| `SourceSnapshot` | 设计 SHA、build ID、最终钻孔快照 SHA、CAD 引擎版本、Library/附件哈希 |
| `TemplateSnapshot` | 模板 ID、版本、固定后的标题栏、样式、标准说明 |
| `Sheet` | 纸张尺寸、方向、图框、页码、默认比例 |
| `View` | 投影方向、剖切定义、来源对象、纸面位置、比例、显示层 |
| `DrawingItem` | 尺寸、文字、标签、引出线、中心线、修订云线等 |
| `Association` | 稳定对象键、Feature/基准/轴线/轮廓步骤关联，以及 valid/broken/needs-review 状态 |
| `Table` | 数据查询定义、固定来源、列格式、分组、位置、用户备注 |
| `UserOverrides` | 移动、隐藏、布局、格式和明确的用户编辑 |
| `DrawingRevision` | 修订号、日期、修改说明、源快照、发行人/记录、PDF 与哈希；可选绘制/检查信息 |
| `DrawingIssue` | 具体绘图问题、受影响对象及处理状态；源工程问题引用已有复核记录 |

生成对象与用户对象分别保存，稳定对象键连接二者。发行例外保存在修订的说明/例外列表中，复用已有工程复核记录，不增加独立审批单据和流程引擎。

### 4.2 坐标与尺寸规则

- 工程坐标始终以 **mm** 保存。
- 图页位置、字高、线宽以**纸面 mm** 保存。
- 视图缩放只改变表现，不改变尺寸数值。
- 尺寸保存测量对象与计算方式，显示值由工程数据计算。
- 禁止通过覆盖尺寸文字伪造测量结果。

### 4.3 持久化

建议使用：

```text
projects/drawings/<project_id>/<drawing_id>/
    当前文档
    保存历史
    发行快照
    受管理附件引用
```

具体文件名在 schema 落地时固定。缓存可重建；发行资料必须可独立保留。保存/自动恢复的技术版本不等于图纸修订号，每次拖动不会创建一个正式修订。

Drawing 使用独立的乐观锁版本。移动尺寸线不会改变 Manifold SHA，也不会使 CAD 构建失效。保存冲突必须返回明确提示并保留本地编辑。

### 4.4 API 与任务

API 覆盖：

- 创建、列出、读取、保存 Drawing。
- 复制 Drawing、创建新修订。
- 生成、检测源变化、预览重新生成结果、应用更新及处理失效引用。
- 图纸检查、修订/历史、发行及必要说明。
- PDF 导出及文件下载；SVG/DXF 适配器独立增加。

耗时生成采用本地任务状态，提供进度、取消和错误详情。读取并固定源快照后再进行计算，提交时复核版本；不能长时间占用全局项目锁。

## 5. 工程来源与最小必要字段扩展

### 5.1 固定真实工程来源

图纸默认使用选定构建的精确 STEP、最终钻孔与固定库定义。

**不得从三角网格量尺寸，也不得在生成图纸时另跑一次布路。**

优先消费已有 STEP、`resolved_design`、加工清单、固定 Library 定义和附件，不要求先建立新的完整构建产物体系。只有现有产物确实无法提供某项必要关联时，才增加最小映射或可重建缓存。旧构建缺少必要信息时明确要求新建构建，不用新引擎偷偷重算并冒充历史结果。

### 5.2 字段扩展准入规则

任何源字段扩展必须能回答：哪一个实际图纸内容需要它、现有 V2.1/Manifold 字段为什么不足、工程来源在哪里、哪些现有校验受影响。先查已有字段/固定资源，再复用或做最小扩展。

优先级固定为：**读取已有工程数据 → 增加绘图显示/引用能力 → 仅为确认的缺口扩展公共工程字段。** 不全面整理 Library，不建立第二套制造主数据，不把所有孔型的工艺补齐作为 V2.3 任务。

| 实际需求 | 最小处理与边界 |
|---|---|
| 螺纹、孔深、材料、孔腔/堵头规格 | 先读固定定义和已有加工信息；绘图仅缺少引用/格式时只增加适配，不重复建立规格库 |
| 个别必要公差、表面或工艺说明 | 已有资源可表达则引用；确实缺字段时增加有来源及复核记录的公共属性，不扩展成完整工艺管理系统 |
| 面坐标、基准 | 先使用已有坐标及工程面；纸面原点/方向存为视图设置，只有实际加工基准缺失时才增加源字段 |
| 安装孔 | 若目标 Manifold 确有绘图必须表达的安装孔且现有模型无法表达，最小扩展公共机械特征；不预先实现所有紧固件/沉孔家族 |
| 安装孔验证 | 任何新增机械切削仍参与实体、壁厚和泄漏/干涉检查，不成为液压节点；图纸文字不能代替实际几何 |
| 堵头入口 | 展示已有可信加工定义；缺失则标明并链接已有工程复核入口，不为出图编造入口几何或开展全库补齐 |
| 刻字 | 优先引用已有要求；必要时增加位置和工艺的公共元数据，不因刻字说明要求实现完整雕刻 CAD/CAM；实际加工日期不由出图日期代替 |
| 加工编号 | 复用 `machining_id` 和 Feature ID；A–F/AA 等纸面显示编号可存于 Drawing，不改变工程身份 |

尺寸、材料、实际孔型和制造要求的权威仍在 V2.1/Manifold 公共数据；更改真实规格通过已有工程入口或最小公共编辑扩展完成。纸面位置、字高、比例、显示编号和自由说明由 Drawing 管理，不能回写为已验证工程事实。

缺失信息按特征定位，只影响依赖它的内容或发行判断；其他有效视图、编辑、保存和审阅 PDF 继续可用。用户自行填写的说明保留来源/复核语义，不因进入图纸就获得 Library 权威。

### 5.3 兼容性

采用兼容旧项目的增量扩展，必须验证：

- 旧 schema version 1 项目可读。
- 旧设计哈希可识别，不因空的新字段无故改变历史身份。
- 历史构建不被重写。
- 新机械特征不削弱原液压特征规则。

## 6. Customer Drawing 工作流

目标是尽快形成可提交客户审核的完整图纸。

1. 在 Project 选择现有 Manifold，点击 **Create Drawing → Customer Drawing**。
2. 选择 PMC Customer 模板，确认图号、标题、客户信息及源版本。
3. 当前没有适用构建时明确显示保存/构建步骤；已有历史构建可作为明确选择的历史来源。
4. 自动生成外形视图、等轴测图、总体尺寸、关键安装/接口尺寸、端口名称和适当的阀/孔腔标识。
5. 放入关联原理图、Porting Table、尺寸/材料信息、刻字说明、一般公差、修订栏及 PMC 标题栏。
6. 用户调整布局、标注及说明，保存、重新打开、检查并导出矢量 PDF；需要正式交付时发行当前修订。

默认采用 PMC26-3092 第 1 页的第三角投影布局和客户信息层次，支持按需要增减视图。复杂接口先通过手动新增图页/调整视图解决，自动分页建议和更复杂详图逐步增强。

未知产品身份和用户选型偏好不得自动进入已确认元件表。例如 `USE SUN CARTRIDGES WHEN POSSIBLE` 仍是选型偏好。可保留明确标识的待确认说明，并允许其他有效内容继续生成。

## 7. Manufacturing Drawing 工作流

### 7.1 默认页面安排

| 页面类型 | 默认内容 |
|---|---|
| 总览页 | 外形、接口/孔腔名称、材料、尺寸、Porting Table、加工说明 |
| 面加工页 | 六面或分组面视图、基准、坐标尺寸、加工编号、孔与螺纹标注 |
| 内部页 | 隐藏线、内部孔道等轴测图、必要剖面、钻孔与堵头明细 |
| 详图页 | 拥挤面、特殊孔型或需要放大的加工细节 |

具体页数由内容决定，不强制每张制造图都是三页。六面坐标、孔标识、隐藏线、表格和手动分页面向核心制造流程；高级自动排版可以稍后增强。

### 7.2 自动尺寸与加工信息

适用项目包括：

- 外形尺寸、基准到孔中心的坐标。
- 直径、半径、角度、深度、孔组及数量。
- 螺纹规格和有效深度。
- 阶梯孔、沉孔、沉头及相关位置。
- 斜钻方向和加工角度。
- 通孔、盲孔、交叉钻孔及堵头入口。
- 有来源的公差、基准和表面要求。

必须明确区分当前系统的**圆柱深度与钻尖总深度**。

交叉孔加工数据来自最终钻孔和实际切削关系，不能把液压连通图直接当成加工路径。

### 7.3 剖视与内部视图的实施优先级

- 核心先完成精确隐藏线、中心线、内部线稿和制造表达确实需要的基本直剖。
- 若某项关键加工信息仅靠六面图/表格无法明确表达，对应基本剖面必须完成，不能以“高级功能”名义省略。
- 阶梯剖、自动局部详图、高级剖切编辑及彩色内部表现仍可在 V2.3 内增强，但不延迟基本生成、编辑、保存和 PDF 流程。
- 剖面来自精确实体；修改剖切定义重新生成该视图，优先保留仍有效的标注关联。
- 内部彩色图仅辅助识别，制造尺寸仍来自精确数据；没有彩色效果时可用可读的矢量线稿完成表达。

### 7.4 缺失信息处理

缺失资料按特征显示清单，例如“PLUG3 缺少入口加工定义”，提供定位和补充入口。其他视图仍可完成。

源记录存在、几何映射完成、加工资料完整以及工程师批准必须分别记录，不能相互替代。

## 8. 视觉编辑工作区

### 8.1 布局

- 顶部：文档、保存、源版本、状态、更新、检查和导出。
- 左侧：图页、视图及图层树。
- 中间：可缩放和平移的图纸画布。
- 右侧：选中对象属性。
- 检查面板：问题清单，可定位到具体图页和对象。

### 8.2 优先完成的 PMC 日常整理操作

| 对象 | 编辑能力 |
|---|---|
| 视图 | 移动、比例、跨页安排、显示/隐藏；保持已有投影方向 |
| 尺寸 | 自动或手工添加、删除、移动、排列、精度、箭头、引线和文字位置 |
| 尺寸关联 | 捕捉边、点、圆心、轴线及基准；后端复核测量值 |
| 标签/引出线 | 添加、文字与编号表现、移动、折点、重新关联 |
| 文字/说明 | 添加、编辑、移动、字体、字高、换行 |
| 可见性 | 按视图控制隐藏线、中心线、标签、尺寸及表格的显示 |
| 表格 | 移动、列宽、行高、分组、排序、续表、备注列 |
| 图页 | 增删、排序、纸张与方向、标题栏 |
| 标题栏/元数据 | 图号、标题、修订、日期、说明及允许编辑的模板字段；工程字段保持源关联 |
| 画布 | 选择、缩放、平移、基本吸附、撤销/重做 |

普通用户应能完成“移开重叠尺寸、补一个关联尺寸、删去重复尺寸、调整说明/引出线、移动视图、整理表格、修改标题栏、撤销误操作”，无需先完成高级通用绘图工具。

多选/批量对齐、高级工程符号工具、复杂裁剪、修订云线、自动避让及高级剖视交互安排在上述流程之后。支持这些增强不能以牺牲日常编辑稳定性为代价。

### 8.3 编辑与来源边界

- 自动标注删除后保存抑制记录，更新图纸时不会无故重新出现。
- 视图移动时关联标注一起移动。
- 尺寸公差、孔规格等工程内容走结构化编辑；自由文字保留为说明。
- 表格中的材料、孔径、螺纹等源字段不能直接覆盖；用户可编辑备注和展示名称。
- 撤销/重做使用 Drawing 自己的操作历史，与 Manifold 编辑历史隔离。
- 提供自动恢复记录，以及明确的“已保存/未保存/冲突”状态。

## 9. 模板与自动排版

### 9.1 内置模板

- **PMC Customer Drawing**。
- **PMC Manufacturing Drawing**。

默认 A2 横向，支持其他常用纸张、方向和多页。

模板包含：

- PMC 公司资料、Logo、图框和标题栏。
- 投影符号、比例、图号、标题、材料和页码字段。
- 修订区域、标准说明和一般公差表。
- 图层样式、字高、线宽及默认视图/表格安排。

样本中的人员、历史日期、材料、数量和具体表面要求不能成为所有新图纸的固定事实。公司资料可维护，标准公差与说明需作为明确的模板工程默认值使用。

### 9.2 模板版本

模板应用后固定版本。以后修改公司模板不会更改已发行图纸。

复用同一模板结构支持两个 PMC 模板及后续模板。先允许复制、设置常用字段/样式并保存模板配置；完整的通用模板设计器不是基本 Drawing 可用性的前置条件。

### 9.3 排版规则

先采用可预测的确定性布局规则：

- 优先保持投影关系、尺寸空间和标题栏边界。
- 标注分层排列，支持坐标标注折线及分组。
- 内容过密时提示并支持手动拆页、拆表；自动分配到新页和详图建议逐步增强。
- 不通过无限缩小文字塞入一页。
- 自动结果允许快速人工调整。

默认正文字高建议 3.5 mm；密集辅助文字低于 2.5 mm 时产生可读性提示。线宽、虚线间距、箭头大小按纸面尺寸保持一致。

## 10. Drawing 与 Manifold 的关联更新

### 10.1 核心更新方式

采用**检测变化 → 预览重新生成 → 按稳定键重用表现 → 明确处理失效引用**的更新流程。不要求先实现通用或复杂的三方合并引擎。

从第一版数据结构开始分开保存生成几何、关联标注、用户布局及独立说明。关联锚点使用 Feature ID、面、轴线、轮廓步骤和来源标识，不能依赖易变化的 OCCT 边序号或网格编号。

1. 打开图纸和发行/导出前比较源设计版本与所选构建，变化时明确显示“Source changed”。
2. 用户选择更新，系统固定新的已有构建并生成候选结果，不覆盖已保存文档。
3. 稳定视图键保留位置/比例；有效对象键保留尺寸文字偏移、标签样式及隐藏/删除记录。独立文字和说明保留。
4. 无法匹配的引用进入失效清单，旧对象保存在待处理区域，不作为当前有效尺寸导出。
5. 用户定位、重新关联、删除或明确转为不带测量权威的说明，再保存更新结果。取消或失败仍保留旧版本。

### 10.2 各类变化的明确行为

| Manifold 变化 | Drawing 行为 |
|---|---|
| 外形变化 | 重算轮廓和相关尺寸，保留稳定视图的位置/比例；超出图框时提示调整 |
| 特征移动 | 更新尺寸值、标签锚点；保留合理的文字偏移 |
| 特征增加 | 加入表格及待安排标注，必要时建议新页 |
| 特征删除/抑制 | 标记失效关联并列入冲突，禁止静默指向邻近孔 |
| 孔型替换 | 重算标注、轮廓与规格；语义变化要求复核 |
| 自动钻孔重建 | 稳定来源键仍成立时保留关联；ID/语义无法可靠对应则标为失效或需复核，不要求首版自动推断对应关系 |
| 固定 Library 版本改变 | 更新对应规格并列出差异 |
| 用户说明和布局 | 独立说明直接保留，有效锚点的相对偏移保留；布局碰撞提示人工整理 |
| 生成表格变化 | 更新源数据，保留列宽、分组和可继续匹配的备注 |
| 原理图变化 | 显示附件版本差异，复核原有页面/裁剪范围 |

更新预览至少列出新增、变化、删除对象和失效引用数量，并可定位尺寸、标签和表格。复杂的逐字段冲突合并 UI 不作为核心要求。

### 10.3 渐进增强

在真实更新案例需要时，再增加更智能的路线/轮廓对应、自动排版修复和选择性更新。任何启发式匹配都必须在歧义时要求复核，不能静默把标注关联到相邻孔。

简单且稳定的重新生成与保留规则本身可以满足核心验收；通用三方合并不作为完成标准。

已发行修订不自动更新，始终对应原来的 Manifold 快照。继续工作必须创建新修订。

## 11. Project 集成与发行生命周期

### 11.1 Project 中的图纸

当前一个 Project 对应一个 Manifold。V2.3 在此基础上增加多个 Drawing 文档，不顺带改造为多 Manifold 装配管理。

```text
Project
├─ Manifold
├─ Customer Drawing
│  ├─ 当前草稿
│  └─ 发行修订历史
└─ Manufacturing Drawing
   ├─ 当前草稿
   └─ 发行修订历史
```

Project 内显示图纸名称、类型、图号、修订、Draft/Released、源是否变化和更新时间，支持创建、打开、复制及新修订。Project 的现有归档操作覆盖其图纸，不新增复杂图纸审批或归档体系。

复制图纸得到新的草稿身份，不复制已批准状态。复制 Project 可复制当前图纸为草稿，并重新绑定新项目；历史发行记录不能冒充新项目批准记录。

永久删除界面需要明确说明图纸处理范围，已发行证据按不可变产物策略保留。

### 11.2 状态与修订

```text
Draft（保存/继续编辑） → 检查并发行 → Released（不可覆盖）

Released → 创建下一修订的 Draft
```

修订号与保存版本分开。后续修订发行后，旧版仍可查看/下载，显示哪个修订为当前版即可，无需增加多层生命周期状态。

每次发行固定：

- 图号、修订号、日期和修改说明。
- 发行人、发行日期及必要说明；绘制/检查字段按 PMC 实际使用填写。
- 对应设计 SHA、构建及 Library 来源。
- 图纸检查结果、工程检查结果和例外记录。
- 实际发行 PDF 与哈希；其他格式若已提供则记录对应版本。

不要求独立 In Review 状态、多级审批、角色权限、签核路由、变更单或 PLM 式配置管理。工程检查由已有验证与复核机制提供，Drawing 只增加与图纸完整性直接相关的检查。

发行检查至少确认源版本、有效引用、尺寸数值、必需信息覆盖和纸面可读性。用户可删除自动尺寸并用其他有效尺寸或表格表达同一加工信息，不强制恢复某一种自动排版；关键信息确实缺失时明确提示所缺内容。

### 11.3 工程例外与严格边界

保留实用的书面例外能力：在本次发行记录中列出受影响内容、工程决定、记录人和适用范围，优先引用现有工程复核项，并随 PDF 可见。存在例外时显示“Released · 有例外”的提示，不新增独立发行状态和审批工作流。

**图纸发行不能把 `manufacturing_ready=false` 改成 true，也不能把原来的 FAIL 改成 PASS。**

无效几何、错误测量、仍作为有效标注使用的损坏引用及导出内容不一致，需修复后才能正式发行。资料或工艺完整性问题可记录明确例外，但不能覆盖既有不可绕过的工程验证边界。

草稿/审阅版始终与正式制造发行区分。

现有系统没有身份认证，本次记录的是本地人员署名与审核过程，不宣称数字签名认证。

## 12. 导出、原理图与打印质量

### 12.1 共用矢量内容

精确二维线稿通过现有 OCCT 的 BRep 投影能力生成，采用显式单位、方向和比例。

PDF 必须使用计算后的线、圆弧、文字和标注位置，保证浏览器与输出一致。SVG/DXF 复用同一矢量内容，不为额外格式建立另一套工程计算或拖延 PDF。

| 格式 | 交付约定 |
|---|---|
| PDF（必须） | 正式主要交付；多页、正确纸张、矢量线条、嵌入字体、完整标题栏和修订信息 |
| SVG（期望） | 优先复用 SVG 画布/场景导出每页；明确 mm 尺寸和比例，保留矢量内容 |
| DXF（期望） | 纸面工程图交换；明确图层、单位、视图比例及不支持的表现；不作为 CAM 刀路 |
| 完整 Project 打包（后续增强） | 复用已有持久化与附件管理；不为打包新增一套配置/生命周期系统 |

### 12.2 PDF

推荐使用 ReportLab，原理图 PDF 的裁剪合成增加专用 PDF 处理层。字体随发行包固定，确保中英文及 Ø、±、深度等符号完整。

技术参考：[ReportLab 字体文档](https://docs.reportlab.com/reportlab/userguide/ch3_fonts/)。

### 12.3 DXF

优先评估复用环境已有 ezdxf；实际采用时再正式列入直接依赖。

先验证典型 PMC 图纸的几何、文字及尺寸交换。原生 DIMENSION、复杂标注兼容或外部 CAD 一致性若需要不成比例的工作，记录支持范围及待办，允许不交付该适配器；不得因此阻塞核心工作区或降低 PDF 质量。不承诺外部 CAD 修改后可关联导回 PMC。

技术参考：[ezdxf 尺寸文档](https://ezdxf.readthedocs.io/en/stable/dxfentities/dimension.html)。

### 12.4 原理图

- 保存原理图附件哈希、页码和裁剪位置。
- 原始 PDF 尽量保持矢量。
- PNG/JPEG 保留原分辨率，并检查有效打印清晰度。
- 原理图作为 Drawing 布局的一部分保存和导出。
- 不重新让 AI 绘制已有原理图。

### 12.5 备份与质量

现有 `.pmc.json` 继续支持，并明确其原有导出范围。核心要求是 Project 内完整保存并重新打开 Drawing、原理图引用和发行记录。单独的完整 Project 包格式属于可继续增强项，不成为基本绘图前置条件；实现时复用现有资源和哈希引用，防止迁移后出现空引用。

### 12.6 额外格式的交付判定

先完成 PDF 验收，再对 SVG/DXF 分别记录代表性样本、适配成本、支持内容及已知限制。成本合理则纳入 V2.3；某格式成本过高时明确记录未交付项及原因，保留适配入口，不阻塞本节定义的核心 PDF/Project 工作流，也不将未实现格式列为已完成。

打印质量检查包括纸张尺寸、比例、线宽、虚线、字体、符号、页码、标题栏、裁剪、表格续页及原理图分辨率。不能将屏幕截图作为正式工程图输出。

## 13. 实施顺序

以下均属于同一个完整 V2.3 的内部实施步骤。先用已有可靠工程数据打通客户/制造两类文档的端到端流程，再完成制造深度、更新和发行；高级能力在可用流程之上增强。

| 顺序 | 实施内容 | 阶段完成证据 |
|---|---|---|
| 1 | 核对完整 9 页参考范围，确认必要输出与已有工程字段；固定最小文档结构、稳定对象键和坐标/比例规则 | 样本需求有数据来源；必要缺口有具体对象和最小扩展说明，没有全库补齐任务 |
| 2 | 共用 Drawing 存储/Project 入口、源快照及变化标识；精确外形/等轴测、基本尺寸/表格、两种 PMC 模板、原理图和首个矢量 PDF 路径 | 同一 Project 可创建两类 Drawing 并生成来源正确的初稿/PDF，不依赖高级合并或额外格式 |
| 3 | 日常视觉整理：尺寸增删移动、说明/引出线/标签、视图位置/比例、可见性、表格、标题栏、撤销重做；保存和重开 | 两类图纸均走通“创建→生成→编辑→保存→重开→PDF”，界面故障和冲突有明确反馈 |
| 4 | 制造表达与多页：六面基准坐标、孔/螺纹/钻孔表、隐藏线、必要直剖和手动分页；仅处理已证实的公共字段缺口 | 有来源的制造案例能整理成可供工程师审核的加工图；必要源扩展通过现有几何/液压测试 |
| 5 | 源重新生成流程：变化预览、稳定键复用位置/比例/标注、保留说明/抑制记录、失效引用定位与重新关联 | 移动/新增/删除/换型/重布路有确定结果；取消不覆盖旧稿，无需通用三方合并 |
| 6 | Draft、修订/历史、Released；发行检查、不可变 PDF、简单发行说明及必要例外 | 新修订可编辑，旧修订可查；源版本、PDF 与检查记录一致，不引入审批状态机 |
| 7 | 三份参考和 CT 密集基准的可读性、必要性能优化、打印检查与核心回归 | 必须能力达到第 16.1 节；人工整理可以完成真实密度图纸，核心流程可独立验收 |
| 8 | 按收益增强自动避让/匹配、详图/阶梯剖、批量工具及 SVG/DXF；逐项验证成本与支持范围 | 合理成本的增强纳入同一 V2.3；未交付项明确记录，不影响已达标核心能力 |
| 9 | 对最终实际交付范围做完整回归和文档整理 | 必须项全部通过，额外格式和高级能力逐项注明实际状态及限制 |

从第 1、2 步就固定精确来源、稳定关联和生成/表现分离，避免返工；复杂的自动协调能力不前置到编辑器和 PDF 之前。必要工程修正随使用它的功能实施，不能扩大成单独的 V2.1 重建项目。

## 14. 测试与验收策略

### 14.1 测试矩阵

| 测试层 | 必须覆盖 |
|---|---|
| 几何与尺寸 | 六面方向、镜像、原点、mm/inch、比例、孔中心、已有斜孔/阶梯孔、钻尖和必要基本剖面 |
| 权威边界 | AI 不确定身份不变成已确认表格；Library 缺项不补造；按需新增安装孔不成为油路；绘图不引入重复事实源 |
| 源一致性 | 图纸引用实际构建与最终钻孔；生成不重新布路；旧快照不重写 |
| 源更新 | 源变化标识、重新生成、特征移动/删除/替换、路线 ID 变化转失效、抑制记录/文字/布局保留、重新关联及取消恢复 |
| 存储/API | 乐观锁、并发保存、任务取消、崩溃恢复、项目复制/删除、现有归档及附件引用 |
| 发行 | Draft/Released、修订历史不可变、必要例外可追踪、检查结果不被发行状态覆盖 |
| 必须导出 | PDF 页尺寸、线宽、字体、符号、比例、裁剪、多页、原理图及源数值一致 |
| 浏览器 | 从 Project 创建到编辑、重开、源更新、复核、发行和下载的实际点击流程 |
| 性能 | CT 同量级多页密集图的生成、缩放、拖动、选择、表格和撤销重做 |
| 已提供的增强 | SVG/DXF 若交付则核验其支持范围及与 PDF 一致性；高级剖视/匹配只对实际交付功能作对应回归 |

### 14.2 真实样本与密集基准

密集基准至少覆盖当前模型规模上限附近的案例，并安排六面视图、剖面、数百条标注和跨页表格。

记录本机硬件与测量结果，目标是编辑过程中无需触发 CAD 重算，常规拖动和缩放持续流畅。

以完整 9 页建立内容对照表，PMC26-3092 第 1 页作为主要客户图，其余页与 CT/Purge 共同检查详细制造表达。真实样本用于布局、信息覆盖和人工工程对照；来源清楚的可重复模型夹具用于验证数值，不把 PDF 反推出来的未知几何冒充真实 CT 模型。

核心验收允许通过日常编辑、明确的人工重新关联和手动分页完成密集图；不把完美自动布局或全自动合并作为通过条件。必要制造信息不能遗漏，单独记录仍需外部工程资料的项目。

### 14.3 必须执行的验证

实施阶段运行：

- 现有工程证明和相关工程测试。
- store/API 测试。
- 前端构建。
- 本地浏览器完整操作与视觉检查。
- PDF 数值、排版和打印质量核查。
- 已交付 SVG/DXF 和高级功能的相应检查；未交付功能不伪报通过。

几何修改必须保留故意失败与修正后的 `python -m manifold prove` 证据。所有 CAD 仍通过 `manifold.cad` 加载，保留 Windows 子进程正常退出测试。

本计划中的测试属于实施验收要求，不代表 V2.3 已实现或已通过测试。

## 15. 重要技术风险

| 风险 | 处理 |
|---|---|
| 绘图扩张成第二个知识库/制造数据项目 | 每项源字段扩展绑定实际绘图缺口，复用 V2.1/Manifold，不全面治理或补齐 Library |
| 布尔重建后边编号变化 | 使用语义关联；歧义进入更新冲突 |
| CT 隐藏线与标注过密 | 优先保证手动分页、图层控制和标注移动可用，再增强自动避让/详图 |
| 库记录完整但加工映射不完整 | 分别呈现来源、几何状态、工艺状态与工程决定 |
| 新机械孔破坏现有液压假设 | 独立特征语义，进入实体和泄漏/干涉检查 |
| 浏览器与导出文字布局不同 | 固定字体、共享字度与布局结果、跨格式回归 |
| 图纸更新覆盖用户整理 | 生成几何与用户调整分开保存；稳定键复用、失效清单和可取消的候选结果，不依赖高级三方合并 |
| 图纸发行被误认为制造认证 | 分开记录图纸状态、工程验证和例外 |
| 生命周期/导出/高级工具拖延核心流程 | 先验收两类图纸的编辑、持久化、关联更新、实用发行和 PDF；额外格式及增强单独记录成本与实际交付状态 |
| Windows CAD 进程问题 | 所有 CAD 仍通过 `manifold.cad` 加载，保留进程退出测试 |

## 16. 完整 Definition of Done

### 16.1 必须完成的 V2.3 验收项

以下条件必须全部成立。它们覆盖完整客户/制造 Drawing 工作流，不以额外格式或高级自动化代替核心能力。

- [ ] 任意现有有效 Project Manifold，不论人工、AI 辅助还是已有导入流程来源，都能进入同一个 Drawing Workspace。
- [ ] Customer 和 Manufacturing 两种模板均能自动生成有用初稿。
- [ ] 客户图包含有来源的外形/接口尺寸、适当视图、端口标识、原理图（已有时）、表格、材料及 PMC 标题栏/说明；第 1 页参考 PMC26-3092。
- [ ] 制造图包含适用的六面坐标、孔腔/端口/钻孔/堵头信息、隐藏线、必要基本剖面及加工表格，可通过多页和人工整理清楚表达。
- [ ] V2.1/Manifold 仍是工程事实来源；仅实现具体绘图所需的最小公共字段扩展，无重复知识库；缺失资料有明确提示且不被编造。
- [ ] 尺寸可新增、删除、移动和调整表现；数值由真实工程关联计算，不能通过文字覆盖伪造。
- [ ] 说明/文字、引出线/标签、视图位置/比例、可见性、表格和标题栏可编辑，缩放/平移及撤销/重做可用。
- [ ] 两类图纸都能完成“创建→生成→编辑→保存→关闭→重开→矢量 PDF”，用户调整及附件引用完整保存。
- [ ] 源变化可检测；重新生成先预览，稳定视图位置/比例、有效锚点的标注偏移、独立说明和抑制记录保留，不能保证的保留明确提示。
- [ ] 删除/换型/重布路导致的失效引用可定位、重新关联或删除，不静默转绑；更新取消/失败不覆盖旧稿，无需高级三方合并才能通过。
- [ ] Project 可管理多个图纸文档及其修订。
- [ ] Draft、修订/历史、Released 完整可用；新修订可编辑、旧修订/PDF 不可覆盖，必要工程例外以简单记录随发行可见。
- [ ] 发行 PDF 与固定源版本一致；源已变化时不能冒充当前模型图纸，原工程 FAIL/制造就绪状态不因发行而改写。
- [ ] PDF 可打印、可提交客户；制造图在资料完整并完成工程复核后，可作为加工交付文件。
- [ ] PDF 为正确纸张/比例的矢量工程文件，线宽、字体、符号、页码、表格和原理图打印清晰，与屏幕布局及源尺寸一致。
- [ ] 三份共 9 页参考的核心内容逐项对照，CT 密集基准完成实测和人工审图；允许人工整理，必要信息不遗漏。
- [ ] 现有工程验证、Library 来源、人工复核及 AI 边界回归通过。
- [ ] 任何生成、更新或导出失败都显示具体原因、受影响对象和下一步，不出现 apparent no-op。

### 16.2 不阻塞核心验收的增强项

SVG/DXF、阶梯剖及高级详图、复杂自动避让、批量工具、通用模板设计器、更智能关联协调、完整 Project 打包均可在同一 V2.3 内继续增强，但不作为第 16.1 节的前置条件。

每项在最终交付记录中标明“已交付 / 有限支持 / 未交付”、原因和实际支持边界。成本合理的增强应完成；不成比例的工作可以保留待办，不能默默删除要求或宣称已完成。任何已交付的额外格式或高级工具仍须通过相应数值、来源和回归检查。

PDF、两类 Drawing、日常编辑、Project 持久化、源关联更新和基本修订发行不得降为可选，也不另命名为 V2.3A/B/C。
