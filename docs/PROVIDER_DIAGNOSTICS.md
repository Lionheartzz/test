# Real multimodal provider diagnostics — V2.2

## Findings from the first operator trials

The reviewed local history contains four failed real attempts (two truncations and two timeouts). Each has one document and a short requirement string. The old adapter threw on `finish_reason=length` **before reading usage**, and timeouts also stored neither usage nor request details. The workspace list displayed only `latest_run` (the last successful result), hiding failed attempts as “Not analyzed”. Old usage cannot be reconstructed; the reported 60,259-token dashboard total cannot be attributed exactly to these records.

The request had no thinking/reasoning controls. DeepSeek documents thinking enabled with high effort by default. This is a plausible source of large output/latency, not proof of what an operator's custom endpoint/model actually did. See [DeepSeek thinking controls](https://api-docs.deepseek.com/guides/thinking_mode/) and [Chat Completions usage/limits](https://api-docs.deepseek.com/api/create-chat-completion/). The prior adapter could also repeat the same images/instructions once after invalid output; it did not retry a truncation or timeout directly. Historical per-request evidence is missing, so the contribution of that retry is unknown.

The previous system prompt/schema was 6,699 characters, including a 4,230-character schema. It was sent once per request; original instructions and each page appeared once, with no assistant/reasoning history. The new schema omits descriptive titles/defaults while keeping validation rules (3,371 characters); the system prompt is 6,337 characters with concise output guidance and an observation example. These are character counts, **not token estimates**. Recognition fields, all-port topology, multi-page interpretation and existing semantic bounds were preserved. The optimization does not replace engineering details with a small-circuit-only prompt.

## Operator controls

Open **AI Design → Provider settings**. Existing saved endpoint/model/key and configured token/timeout values are retained; this fix does not rewrite the configuration file.

- **Maximum output tokens:** any positive whole number, no PMC upper bound. Blank omits the parameter. Decimal-string UI submission preserves even integers beyond JavaScript's safe-number range. There is no silent clamp, reduction or retry with a smaller value. Choose `max_tokens` or `max_completion_tokens` as supported by the endpoint. Provider/model context and output limits still apply; leaving blank can select a large provider default, not necessarily a cheaper one.
- **Reasoning parameter dialect:** `Provider default` sends no controls; `reasoning_effort` maps the selected mode/effort to that field; `thinking.type + reasoning_effort` supports endpoints documenting those controls. Neither endpoint URLs nor model names trigger automatic dialect selection.
- **Thinking mode / Reasoning effort:** select the desired controls. Disabling thinking takes precedence over an effort; any omission is recorded. A mode/effort without a dialect is not sent and is explicitly flagged in run diagnostics. Providers may ignore or reject controls; HTTP rejection identifies a recognized parameter without exposing error prose. A successful request records requested-but-unverified support, not an assertion that the model honored it.
- **Reasoning task:** default controls can be overridden for current schematic extraction (`hydraulic_understanding`). Future topology/optimization operation settings are stored separately; these labels do not introduce those operations into the current generator.
- **Automatic contract retries:** default **None**. Explicitly choosing one permits a second request only after semantic JSON/schema or normalization failure. It reuses the source context with a short correction instruction; no provider response or reasoning text is replayed. Both attempts retain their own evidence. There is no fallback to mock output.
- **Stream provider response:** optional, for compatible SSE endpoints. `Request streaming usage statistics` controls `stream_options.include_usage`. Keep streaming off for endpoints that do not support it. A final usage-only event and usage on the last content event are both supported.

The previous fixed 2 MB transport and serialized-result gates were removed so they cannot act as hidden token ceilings. Semantic admission and document limits remain in force. Large non-streaming responses need corresponding local memory; streaming discards reasoning text as it arrives and retains only the semantic content for parsing.

## Diagnostics and failure behavior

Each attempt records phase, HTTP status, normalized finish reason, known rejected parameter, latency, response bytes, content/reasoning character counts and provider-reported input/output/reasoning/cached/total tokens. No character-to-token estimation is performed. The reader accepts common Chat Completions usage aliases, including nested reasoning/cached fields and DeepSeek cache-hit tokens. It does not assume all providers return them.

Usage is captured **before** checking truncation or parsing the semantic content. SSE cumulative usage snapshots replace earlier snapshots; they are not summed. Across retries, all-request totals require a final reported value from every attempt; otherwise the field is **Unavailable**. A separate reported subtotal includes available partial data and can understate billing. Reasoning and cached fields are not added on top of provider totals. No cost is inferred from token counts; existing optional cost/currency data remains available when a provider adapter reports it.

A valid SSE stream ending with `[DONE]` may omit `finish_reason`; diagnostics retain null/unavailable rather than inventing `stop`. Collected content still undergoes JSON/schema, semantic and normalization checks. Explicit `length` and `content_filter` retain their failure behavior. EOF or usage alone without `[DONE]` is insufficient completion evidence; malformed SSE and unusable content remain rejected. This behavior is provider-neutral.

A single asynchronous deadline bounds all HTTP attempts, including a stream that continues emitting chunks. Timeout closes the local response/connection; it cannot guarantee cancellation of upstream work or billing. If a provider sends usage only at completion, a timeout can still have unavailable usage. Rendering is a separately bounded phase and contributes to the overall run latency.

Failure stages distinguish rendering, provider call, response envelope parsing, semantic schema validation, normalization and later hydraulic admission/knowledge processing. Known timeout, length, authentication, rate-limit, network, unsupported-media, HTTP-parameter and malformed-response errors have actionable messages. Truncation, HTTP/auth/rate/network and timeout failures are never automatically retried.

The analysis list exposes **latest attempt**, independently of the latest successful result. Opening a failed attempt shows its status, provider/model, duration, guidance and diagnostics above the inputs. History still opens previous successes. Background jobs keep the specific failed run and code rather than calling an unsuccessful analysis “completed”. Legacy runs show missing metrics/stage/retry count as unavailable and remain immutable.

Structured-output failures retain each validation path (including zero-based array indices), validation type and a fixed safe explanation. Known schema fields remain exact; unknown property names are redacted because they can contain provider-generated private text. Input values and arbitrary validator context/messages are excluded. Details survive persistence and exports and appear automatically in the per-attempt UI. An explicitly enabled contract-repair retry receives these same sanitized errors, without the rejected response body.

Schema violations and semantic invariants are labeled separately; a schema violation is not proof that normalization is harmless. The strict model/canonical contracts remain in force. A narrow adapter recovery described below can discard unsupported optional identity before revalidation. Other violations remain rejected. Historical attempts that stored only an error count cannot recover field-level details: a newly authorized run is required.

The targeted component contract correction allows an omitted component-level `source` to default to unknown. Its label remains an uncertain inference downstream; this default supplies no provenance for manufacturer, model, cavity or functional type. Those canonical fields remain Observation objects; the conservative provider-boundary shorthand adapter below does not establish identity authority. The prompt explicitly represents `USE SUN CARTRIDGES WHEN POSSIBLE` as a component-selection preference, preserving independent schematic observations. A non-null component observation citing the same user quote as an explicit component-selection preference is rejected; this guard does not independently verify whether model-extracted schematic evidence is true. Source/page checks and canonical engineering rules remain in force.

The prompt distinguishes inferred hydraulic-symbol functional types from explicitly documented types. Only a non-null `functional_type` Observation with absent/unknown source kind receives conservative `ai_inference` provenance; clear or omitted status becomes uncertain. Explicit wrapped unknown-status/non-null contradictions and malformed sources remain rejected. Explicit schematic provenance retains the existing source checks. Normalized inferred claims remain uncertain and do not constitute engineer acceptance.

The current prompt asks for unknown product identity instead of guessed completion. When all initial contract failures are missing provenance or `status=unknown` with a non-null value on manufacturer/model/cavity Observation objects, the adapter discards those values, replaces them with unknown/null, and revalidates the complete result. For the unknown/value contradiction, any explicit source is retained for the normal document/page/quote checks; it does not establish identity. The adapter does not label discarded values inferred products, borrow component provenance or turn selection preferences into facts. Normalization emits field-specific review items; persisted diagnostics retain exact paths with `action: normalized`, never unsupported values. The analysis can complete with useful topology while product selection remains unresolved. Malformed objects, mixed critical errors, invalid source references and semantic/topology failures still reject the attempt.

Failed-analysis UI reads those safe diagnostic categories and displays the affected component/port ordinal and known field name. It does not print raw JSON, internal IDs or validation dumps. If the original response is not retained, an ordinal is not a guessed schematic item name. Recovery uses the already received response without another provider request and does not change operator settings.

Prompt revision `circuit-reading-1-compact-v7` explicitly assigns interpretation of free-form schematic annotations to the AI. There is no required caption layout, token order or delimiter. The AI separates observed model/ordering code, cavity, function and instance context into the existing fields with independent source quotes, while retaining genuine ordering suffixes. Repeated physical components keep separate display labels and ports, without adding instance qualifiers to their observed product identities. This corrects the extraction instructions rather than adding a fixed-format splitter or fuzzy runtime match. Existing saved results remain unchanged; the new contract is used on the next operator-initiated analysis. No additional paid call was made to verify model compliance.

Prompt revision `circuit-reading-1-compact-v8` adds an optional `mounting_interface` observation alongside `cavity`, using the same source/status/review boundaries. An independently confirmed engineering interface can resolve an existing physical definition without a cartridge SKU. Cartridge identities continue to use the compatibility whitelist; an explicitly declared interface must also agree with that whitelist. Conflicting declarations, ambiguous physical variants and missing unit/geometry remain blocked. Legacy compact analyses continue to load; their existing confirmed cavity declarations can use the same independent-interface path when no cartridge identity exists. Inferred function or solenoid actuation cannot establish a mounting size.

AI generation now exposes a generic component-interface catalogue, retaining the legacy `cartridge-cavity` API role for callers. It reads names/families from the same active SQLite definitions and caches the small identity index by database path/mtime, without source archives or CAD work. Case, punctuation and spacing are normalized for catalogue search across all existing families. Documented ISO 4401 / CETOP / NG aliases cover the common size families, not one SKU; these are search/display identities, not equivalence between machining variants. Original IDs, geometry and port/orientation variants remain distinct. Enter and the Search button use the same request with stale-response guards. No geometry, compatibility allowlist or database schema/data is changed.

Prompt revision `circuit-reading-1-compact-v9` keeps full Observation objects as the preferred output, but the provider adapter can process scalar/null shorthand at known observation fields. Null becomes unknown/null; a finite, representable scalar becomes an uncertain `ai_inference` reading. It never borrows component evidence or invents quotes/pages. Component identities, functional types, component/external-port nets, port specifications and parameter readings share this treatment. Missing fields, arrays, malformed objects, non-finite/lossy numbers and extra fields are not repaired. The whole canonical contract and normalization are revalidated, including blocked/connected conflicts, net naming, unique labels and source/quote integrity. No additional provider request is made.

Unconfirmed scalar values are retained separately in compact analysis intent as `unconfirmed_observations`, with an explicit review label. They do not populate confirmed `facts` or `identity_valid`, feed automatic engineering defaults, resolve cartridge/cavity identities or qualify ratings. Net membership remains the exact grouping proposed by the provider, with the canonical connection's status/kind retained and shown as unconfirmed when applicable. New analyses with uncertain connections require the existing explicit topology decision before draft generation; this does not rewrite their original claims or fabricate source evidence. Diagnostics retain only the original input **type** and safe correction paths; raw responses/values are not added to diagnostics. Older attempts lacking input-type metadata remain unknown, not guessed. Successful analysis is still a proposal, not manufacturing approval.

Prompt revision `circuit-reading-1-compact-v10` separates the original engineering requirements, encoded as a verbatim JSON string, from project-unit metadata. Empty or whitespace-only requirements must produce an empty requirements list; drawing notes, reference facts and prompt examples are not user instructions. During normalization, a returned RequirementReading with a blank/nonmatching quote is discarded in full before creating any claim, evidence, mounting data or design intent. The analysis retains a review item explaining that the unsupported instruction was not applied, and diagnostics retain its safe category/location in `normalization_omissions`. This is an omission, not fabricated user evidence or an accepted constraint. The original user-clause coverage check still reports actual instructions left uninterpreted. Exact matching is unchanged for accepted requirements and all Observation evidence; invalid document/page references, identity provenance and topology remain fatal. Historical failures are not rewritten and no additional provider call is made by this handling.

Prompt revision `circuit-reading-1-compact-v11` reinforces that a product code mentioned in a display label must also be captured independently in `model`, while its machining interface belongs in `cavity` or `mounting_interface`. Local symbol port numbers are distinct from hydraulic net names. Runtime identity resolution can also interpret a confirmed model-field designation as an engineering interface when there is no runtime product match and the **whole** designation exactly matches the typed interface catalogue. This uses the same existing direct-interface path, without parsing display labels, stripping product suffixes, promoting inferred observations or inventing cartridge compatibility. Known or ambiguous product matches keep their product semantics. Explicit conflicting interface declarations, multiple physical variants, missing project units, unusable geometry and nonmatching port labels remain blocked. The saved result is immutable: the run GET endpoint adds separate current `identity_interpretations` metadata for display; generation uses the same interpretation and does not stamp an interface code as a product model. Candidate cards distinguish imported/custom/legacy definitions, unit context and actual machining depth. Original analysis exports retain original facts.

Prompt revision `circuit-reading-1-compact-v12` changes the analysis pipeline: (1) the configured model transcribes source identity captions without first assigning product/cavity roles; (2) a read-only local index searches identity fields across runtime, technical and Main Station SQLite records; (3) the same configured model receives the images, original requirements and retrieved reference matches to produce the hydraulic interpretation. This is two planned model requests, with the existing contract-retry allowance shared across both stages and one common configured timeout. It needs no vendor-specific tool-calling capability and does not alter model, token, reasoning, JSON or streaming settings. Per-attempt stage, prompt hash, text/image counts and actual usage are recorded; planned stages are not counted as retries.

Retrieval covers product/full-part/base-model/alias/manufacturer fields, cavity and mounting families, ports, threads, materials, closures, tooling, modifiers and imported Main Station identity fields. It searches the whole indexed domain, then returns bounded candidates per role with match kind, total/returned counts, states and any explicit field truncation. Exact identity fields outrank generic manufacturer/function matches. Reference-only, inactive, unresolved and similar records grant no execution permission. Function context uses the existing central fact resolver with its scope/conflict gates. Catalogue similarity never rewrites a source code or creates compatibility, machining or a source quote.

The typed source-caption reading is retained separately from final identity claims. Components reference its caption ordinals and retain their original text for review; unassigned captions remain visible instead of disappearing. Long captions remain in source evidence even when they cannot fit a scalar claim. Final hydraulic-stage failures can retain the already validated source reading. Identity strings preserve Unicode letters and full ordering suffixes. The production service now uses the SQLite exact-identity resolver instead of the disconnected placeholder; geometry, unit, compatibility and port mapping are still decided by the existing preflight. ## Next real test

Keep the working endpoint, model and key. For an endpoint that documents DeepSeek-compatible controls, choose the `thinking.type + reasoning_effort` dialect and start with **Enabled / low** for schematic extraction. This is an operator test choice, not a new preset or a promise of recognition quality. Preserve the schematic, requirements and image resolution so results are comparable. For other endpoints, choose their documented dialect.

Leave automatic retries at **None** for a clearly attributable first run. Choose your own output budget or blank for the provider default. Keep the current timeout initially; change it based on the reported phase/usage and intended reasoning workload. Enable streaming only if your endpoint supports SSE and its usage option. After one run, inspect the final/partial usage, reasoning count and failure phase before deciding on another test. No additional paid calls were made during this corrective work.
